# 第 5 步：飞书机器人回复

## 接入方式

`app/integrations/feishu/messages.py` 使用官方 SDK 的 `client.im.v1.message.reply`，对收到的消息调用：

```text
POST /open-apis/im/v1/messages/{message_id}/reply
```

请求类型为 text，content 用 JSON 序列化生成，支持中文、换行、引号和反斜杠。回复关联原始 message_id，不接受外部指定接收人，不另行发送到任意用户或群聊。用户需在应用可用范围内，应用需开启机器人能力并开通、发布消息发送权限。

长连接启动时已接入真实发送器，无需增加配置项；复用 `.env` 中的飞书凭据。SDK 负责 tenant_access_token 获取和缓存。HTTP 超时沿用客户端的 20 秒设置，网络异常或 API 拒绝最多发送三次，重试间隔 1、2 秒。

## 回复覆盖范围

- 绑定成功、重复绑定、用户名不存在、账号已关联其他飞书、当前飞书已绑定其他账号及账号停用。
- 未绑定账号发送 PDF 的绑定提示。
- 收录成功：购买方抬头、金额和发票号码。
- 同用户重复：已存在提示和发票号码。
- 跨用户重复：已被其他用户收录，不披露对方身份或详情。
- OCR 失败或信息不完整：原 PDF 已保留、Web 补录提示。
- 非 PDF、异常或加密 PDF、文件过大、下载失败及处理期间绑定变更。

群聊、机器人消息及尚未支持的非文件消息类型仍按接收模块规则忽略，不主动发送回复。

## 回复失败恢复

接收器在业务处理完成后、发送回复前，以原子写入方式将 `MessageResult` 保存在事件目录的 `<消息哈希>.result`。记录包括源消息 ID、源 open_id、回复文本和发送状态，文件权限为 0600，不新增数据库表。

1. 首次处理：保存业务结果，发送回复，保存 delivered=true，删除待处理事件 `.json`。
2. 发送失败：保留 `.json` 和 delivered=false 的 `.result`，下次启动回放时只重新发送原回复，不执行绑定、下载、OCR 或入库。
3. 回复成功但写入发送状态失败：保留原结果，并使用相同 UUID 重试，让飞书服务端在其去重窗口内抑制重复请求。
4. 已保存成功状态：即使进程重启或内存去重缓存过期，再次收到同一事件也会跳过处理和发送。
5. 收据损坏或源身份不匹配：不重新执行业务，保留文件并记录错误，供管理员检查。

每个源 message_id 生成固定 UUID，重试和重启时保持一致。飞书服务端对相同 UUID 的去重有时间窗口，不能承诺任意长时间内严格只发送一次：若远端已经发送成功、本地还未保存成功状态便中断，恢复时间超过远端去重窗口时仍可能重复回复。发票入库不受此问题影响，仍由数据库唯一约束保证幂等。

`.result` 收据保留用于跨重启去重，包含回复中的发票信息，应与数据库、原文件一起保护和备份。删除收据后会失去对应消息的长期发送去重记录。失败超过三次后不无限重试；保留待处理事件，在重启后恢复。

## 验证

```bash
.venv/bin/python -m unittest discover -s tests -v
```

测试覆盖 SDK 请求结构、中文和特殊字符序列化、UUID 稳定性、网络/API 错误重试、发送失败后恢复绑定成功原文、发票已入库后的回复恢复、损坏收据，以及远端发送成功而本地记录失败的恢复。

自动测试通过模拟 SDK 响应验证，不实际向飞书用户发送测试消息。真实回复需启动服务后由用户向机器人发送消息；Web 注册页面将在第 6 步实现，因此当前尚无正式注册入口。
