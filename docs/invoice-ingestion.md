# 第 4 步：发票下载、OCR 与去重入库

## 处理流程

1. 已绑定且启用的飞书用户单聊发送 `.pdf` 文件。
2. 按 `feishu_message_id` 检查历史记录，已经入库的消息直接返回已有处理结果，不重复下载、识别或入库。
3. 使用飞书消息资源接口 `GET /open-apis/im/v1/messages/{message_id}/resources/{file_key}?type=file` 下载附件；失败最多重试两次，即总共三次，间隔 1、2 秒。
4. 限制文件大小为 10 MiB，校验 PDF 标识、可解析性、页数及加密状态。文件名后缀不能代替内容校验。非 PDF、空文件、损坏或需要密码的文件不入库。
5. 完整原始 PDF 原子保存至数据库同目录的 `invoices/<user_id>/<消息ID的SHA256>.pdf`，不使用用户提供的文件名构造路径。文件权限为 0600。
6. 调用阿里云官方 `RecognizeInvoice` SDK，通过 PDF 二进制 body 上传原文件，显式设置 `PageNo=1`。每个 PDF **仅识别第一页**，其余页面不生成额外发票记录；后续打印同样仅取第一页。
7. 提取发票代码、号码、日期、购买方、销售方、价税合计、类型和购买方税号。代码和号码使用字符串保留前导零；日期转为 `YYYY-MM-DD`，金额通过 Decimal 校验至分。
8. 完整有效的结果标记 active；字段缺失、无效或识别失败则保存 pending 和内部错误原因。缺失标识使用 NULL，不伪造发票代码或号码。
9. 在短 SQLite 写事务中重新验证用户绑定和启用状态，再检查消息 ID 和全局发票唯一键。网络请求不占用数据库事务。
10. 根据购买方名称匹配或创建当前用户的常用抬头，再保存发票和关联抬头。已有抬头的税号不自动覆盖。

## 结果与去重

- 同用户重复：返回“该发票已存在，未重复收录”，包括当前识别的发票号码。
- 跨用户重复：返回“该发票已被其他用户收录，未重复入库”，不返回对方用户信息或发票详情。
- 已报销、已排除和已知完整标识的待确认记录同样占用全局去重键。
- 同一消息再次投递不会生成第二条记录；并发提交同一发票时，由写事务和数据库唯一约束保证只入库一张。
- 重复发票本次下载的副本会清理，已有记录对应的原文件保留。
- 支持数电发票；无代码时以 NULL 保存，按发票号码全局去重，仍自动归类购买方抬头。
- 下载失败返回重新发送提示，不创建没有原文件的待确认记录。
- 识别失败最多重试两次，每次重新打开输入文件，避免重试时上传空流。连续失败后保留原始 PDF 并保存 pending。
- 信息不完整的成功响应直接保存 pending，避免重复消耗 OCR 调用。
- 处理期间解绑或停用账号时，不写入发票；原文件保留。原有消息 ID 不允许转移至另一个账号。

第 5 步已接入实际飞书回复。业务结果先持久化，再发送到原消息；发送失败后的恢复不会重新执行 OCR，详见 `feishu-replies.md`。

## 配置

在项目根目录 `.env` 填写：

```dotenv
ALIBABA_CLOUD_ACCESS_KEY_ID=填写阿里云AccessKey_ID
ALIBABA_CLOUD_ACCESS_KEY_SECRET=填写阿里云AccessKey_Secret
ALIYUN_OCR_ENDPOINT=ocr-api.cn-hangzhou.aliyuncs.com
```

缺少阿里云凭据时不调用远端，收到的有效 PDF 保存为 pending，原始文件保留。启用真实识别需开通对应 OCR 服务并授予 `ocr:RecognizeInvoice` 权限。调用可能消耗免费额度或按量计费。

安装新增依赖后，按 `docs/feishu-events.md` 启动应用即可启用链路。现有数据库无需修改表结构。

## 验证与边界

运行：`.venv/bin/python -m unittest discover -s tests -v`。

新增测试覆盖：官方 SDK 请求模型、消息资源下载和重试、体积限制、异常及加密 PDF、原文件保留、多页 PDF 的第一页参数、OCR 返回字段解析、金额和日期验证、失败降级、重复消息、同用户及跨用户去重、并发提交、解绑竞态和存储后恢复。

飞书 SDK 下载接口先将响应加载到内存；本服务在读取其返回流时检查 10 MiB 上限。后续若需处理更大附件，应改用流式下载并重新评估 OCR 限制。

业务数据入库后不对事件重放自动重新识别 pending，以免重复计费；后续 Web 页面支持手动补录。异常重启发生在 OCR 成功与数据库提交之间时，仍可能再次调用 OCR，但数据库不会重复入库。

官方参考：[阿里云 RecognizeInvoice](https://help.aliyun.com/zh/ocr/developer-reference/api-ocr-api-2021-07-07-recognizeinvoice)、[飞书消息资源下载](https://open.feishu.cn/document/server-docs/im-v1/message-resource/get)。
