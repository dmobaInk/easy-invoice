# 发票小助手 - 飞书机器人版开发文档

## 1. 项目目标

开发一个个人发票管理工具，支持多用户使用。用户通过飞书单聊向机器人发送发票 PDF，后端自动识别发票信息、去重入库，并在 Web 端提供发票管理、抬头归类、报销组合推荐和 A4 双拼 PDF 打印功能。

## 2. 技术栈

- 后端：Python FastAPI
- 数据库：SQLite
- 文件存储：本地磁盘
- 飞书接入：飞书开放平台企业自建应用机器人（长连接模式）
- 事件接收：飞书长连接 WebSocket
- OCR：阿里云增值税发票识别 API
- PDF 处理：PyMuPDF / reportlab
- 异步任务：asyncio + threading 或 Celery（可选）

## 3. 用户角色

- 管理员：可以管理所有用户、查看系统日志。
- 普通用户：只能查看和管理自己的发票、抬头和报销记录。

## 4. 核心功能

1. 飞书单聊接收发票 PDF。
2. 调用阿里云 OCR API 解析 PDF，提取发票抬头、金额、开票日期、发票代码、发票号码。
3. 基于"发票代码 + 发票号码"进行去重。
4. 按用户和抬头归类发票。
5. Web 端查看、筛选、修改发票信息。
6. 报销时选择抬头和目标金额，推荐最优发票组合。
7. 一键生成 A4 双拼 PDF，用于打印。
8. 多用户隔离，每人只能访问自己的数据。

## 5. 飞书接入方案

### 5.1 应用类型

使用 **飞书企业自建应用机器人**。

### 5.2 必要权限

- `im:message`
- `im:message.p2p_msg:readonly`
- `im:message:send_as_bot`
- `im:resource`

以上权限必须在飞书开放平台开通，并发布版本后生效。

### 5.3 事件订阅

订阅事件：`im.message.receive_v1`。

接收方式：**长连接（WebSocket）**。

- 本地开发和服务器部署均使用飞书长连接模式，无需公网域名和 HTTPS 证书。
- 飞书 SDK 会维持一个 WebSocket 长连接到飞书服务器，事件推送由 SDK 自动处理。

### 5.4 对外共享

在版本管理与发布中开启：

- 允许外部用户与机器人单聊。

外部用户首次单聊时，可以选择是否需要应用所有者审核。开发阶段建议关闭审核，方便测试。

## 6. 消息接收流程

1. 用户在飞书单聊中向机器人发送 PDF 文件。
2. 飞书通过长连接推送 `im.message.receive_v1` 事件到后端。
3. 后端判断 `chat_type` 是否为 `p2p`。
4. 后端判断 `message_type` 是否为 `file`。
5. 从事件中获取 `message_id`、`sender.open_id` 和文件信息。
6. 使用飞书文件下载接口下载 PDF。
7. 调用阿里云增值税发票识别 API 解析 PDF。
8. 校验发票代码和发票号码是否已存在。
9. 如果已存在，标记为重复并回复用户。
10. 如果未重复，写入 SQLite 数据库并回复用户。

## 7. 用户识别与多用户隔离

### 7.1 用户识别

飞书单聊事件中会包含发送人 `sender.open_id`。

系统维护一张映射表：

```
feishu_open_id -> user_id
```

首次收到某个 `open_id` 的消息时，自动创建用户。

### 7.2 数据隔离

所有发票、抬头、报销单、打印任务表都必须包含 `user_id`。

查询时默认带上当前用户过滤条件，禁止跨用户访问。

## 8. 发票去重规则

去重键为：

```
invoice_code + invoice_number
```

即发票代码 + 发票号码。

同一用户的相同发票代码和发票号码只允许存在一条。

如果不同用户发送了同一张发票，系统应提示"该发票已被其他用户收录"，但仍可根据业务需求决定是否允许入库。默认建议不允许重复入库。

## 9. 发票识别 - 阿里云 API

### 9.1 API 说明

使用 **阿里云智能视觉开放平台** 的 **增值税发票识别** API。

### 9.2 接入方式

1. 在阿里云控制台开通"增值税发票识别"服务。
2. 获取 AccessKey ID 和 AccessKey Secret。
3. 将 PDF 文件转为 Base64 编码或上传至 OSS 获取 URL。
4. 调用阿里云 OCR API 接口，传入图片/Base64。
5. 解析返回的 JSON 结果，提取发票关键字段。

### 9.3 需要提取的字段

从阿里云 OCR 返回结果中至少提取：

- 发票代码
- 发票号码
- 开票日期
- 购买方名称
- 价税合计金额
- 销售方名称
- 发票类型（电子发票/纸质发票/增值税专用发票等）
- 原始文件路径（本地存储路径）

### 9.4 失败处理

- 阿里云 API 调用失败时（网络异常、配额超限等），保留原始 PDF 文件，标记发票状态为 `pending`（待确认）。
- 允许用户在 Web 端手动补录或修正发票信息。
- 建议实现重试机制（最多重试 2 次），连续失败后标记为识别失败。

## 10. 数据库设计

### 10.1 说明

本项目使用 **SQLite** 作为唯一数据库，适合个人/小团队部署场景，无需额外安装数据库服务。使用 `aiosqlite` 或 `sqlite3` 进行交互。

### 10.2 users

- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- feishu_open_id (TEXT UNIQUE)
- name (TEXT)
- created_at (DATETIME)
- updated_at (DATETIME)

### 10.3 invoice_titles

- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- user_id (INTEGER, FOREIGN KEY -> users.id)
- title_name (TEXT)
- tax_number (TEXT)
- created_at (DATETIME)

用于保存用户常用的发票抬头。

### 10.4 invoices

- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- user_id (INTEGER, FOREIGN KEY -> users.id)
- invoice_code (TEXT)
- invoice_number (TEXT)
- invoice_date (TEXT)
- buyer_name (TEXT)
- seller_name (TEXT)
- amount (REAL)
- currency (TEXT, DEFAULT 'CNY')
- status (TEXT, DEFAULT 'active')
- file_path (TEXT)
- feishu_message_id (TEXT)
- created_at (DATETIME)
- updated_at (DATETIME)

唯一索引：`user_id + invoice_code + invoice_number`

状态字段包括：

- pending：待确认（OCR 识别后需人工确认）
- active：可用
- reimbursed：已报销
- excluded：已排除

### 10.5 reimbursement_plans

- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- user_id (INTEGER, FOREIGN KEY -> users.id)
- title_id (INTEGER, FOREIGN KEY -> invoice_titles.id)
- target_amount (REAL)
- selected_invoice_ids (TEXT, JSON 格式存储发票 ID 列表)
- total_amount (REAL)
- created_at (DATETIME)

用于保存一次报销方案。

### 10.6 print_jobs

- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- user_id (INTEGER, FOREIGN KEY -> users.id)
- reimbursement_plan_id (INTEGER, FOREIGN KEY -> reimbursement_plans.id)
- pdf_path (TEXT)
- created_at (DATETIME)

### 10.7 去重日志表（可选）

- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- user_id (INTEGER)
- invoice_code (TEXT)
- invoice_number (TEXT)
- reason (TEXT, 记录重复详情)
- created_at (DATETIME)

## 11. 后端接口设计

### 11.1 飞书事件接口（长连接模式）

- 长连接模式下，飞书 SDK 自动维持 WebSocket 连接并接收事件，无需额外的 HTTP 回调接口。
- 事件回调由飞书 SDK 的回调函数处理，应用启动后自动连接飞书服务器。

处理逻辑：

1. SDK 接收 `im.message.receive_v1` 事件。
2. 过滤非单聊消息。
3. 过滤非文件消息。
4. 下载 PDF。
5. 异步调用阿里云 OCR API 解析。
6. 执行去重检查。
7. 写入 SQLite 数据库。
8. 通过飞书消息接口回复用户。

### 11.2 用户接口

- POST `/api/auth/feishu/bind`
  - 绑定飞书 open_id 与当前登录用户。
- GET `/api/users/me`
  - 获取当前用户信息。

### 11.3 发票接口

- GET `/api/invoices`
  - 查询当前用户发票列表。
- GET `/api/invoices/:id`
  - 获取发票详情。
- PUT `/api/invoices/:id`
  - 修正发票信息。
- DELETE `/api/invoices/:id`
  - 删除或作废发票。

### 11.4 抬头接口

- GET `/api/titles`
- POST `/api/titles`
- PUT `/api/titles/:id`
- DELETE `/api/titles/:id`

### 11.5 报销组合接口

- POST `/api/reimbursements/optimize`
  - 请求体：
    - title_id
    - target_amount
    - allow_exceed：是否允许略超目标金额
  - 返回推荐发票组合。

### 11.6 打印接口

- POST `/api/print/generate`
  - 根据选中的发票生成 A4 双拼 PDF。
- GET `/api/print/:id/download`
  - 下载生成的 PDF。

## 12. 智能报销组合算法

输入：

- 用户 ID
- 抬头 ID
- 目标金额
- 可用发票列表

输出：

- 一组发票，使总金额最接近目标金额。

实现建议：

1. 先筛选该抬头下状态为 `active` 的发票。
2. 按金额降序或升序排序。
3. 使用贪心算法或动态规划求解最接近目标金额的组合。
4. 如果允许略超，则返回不超过目标金额的最优解，或略超但最接近的解。
5. 返回结果中必须包含每张发票的 ID、金额和合计金额。

## 13. A4 双拼 PDF 生成

要求：

- 每张 A4 页面上下排列两张发票。
- 发票图片保持清晰可读。
- 如果发票数量为奇数，最后一页只放一张。
- 输出 PDF 可直接下载打印。

实现步骤：

1. 将每张发票 PDF 转为图片（使用 PyMuPDF 的 `page.get_pixmap()`）。
2. 按两张一组分组。
3. 使用 reportlab 创建 A4 画布。
4. 将第一张发票图片绘制到上半部分。
5. 将第二张发票图片绘制到下半部分。
6. 导出合并后的 PDF。
7. 保存文件路径并返回下载链接。

## 14. Web 端页面

### 14.1 登录页

- 支持账号密码登录。
- 后续可扩展飞书扫码绑定登录。

### 14.2 发票列表页

- 展示发票列表。
- 支持按抬头、金额、日期、状态筛选。
- 支持手动修正识别结果。

### 14.3 抬头管理页

- 新增、编辑、删除发票抬头。
- 显示每个抬头下可用发票数量和金额。

### 14.4 报销助手页

- 选择抬头。
- 输入目标金额。
- 查看推荐发票组合。
- 勾选确认后生成打印 PDF。

### 14.5 打印任务页

- 查看历史生成的打印文件。
- 重新下载 PDF。

## 15. 飞书回复文案

成功收录：

```
已收录发票。
抬头：{buyer_name}
金额：{amount}
发票号码：{invoice_number}
```

重复发票：

```
该发票已存在，未重复收录。
发票号码：{invoice_number}
```

识别失败：

```
发票识别失败，请在 Web 端手动上传或补充信息。
```

## 16. 错误处理

- 阿里云 OCR API 调用失败时，保留原始 PDF，标记发票状态为 `pending`，并记录错误日志。
- 飞书文件下载失败时，记录日志并重试（最多 2 次）。
- 用户发送非 PDF 文件时，回复提示仅支持 PDF 发票。
- 重复发票不写入可用发票表，但可记录到去重日志表。
- SQLite 数据库文件建议放在项目配置目录中，定期备份。

## 17. 部署说明

- 全程使用飞书长连接模式，无需公网域名和 HTTPS 证书。
- 应用启动后自动建立 WebSocket 长连接到飞书服务器，保持在线即可持续接收事件。
- 阿里云 OCR API 的 AccessKey ID 和 AccessKey Secret 不得写入代码仓库，应通过环境变量注入。
- 上传的 PDF 文件按 `user_id` 分目录存储。
- SQLite 数据库文件（.db）需纳入版本管理的 .gitignore，但建议提供初始化 SQL 脚本。
- 建议配置进程守护（如 systemd 或 supervisor），确保服务异常退出后自动重启。

## 18. 验收标准

1. 外部飞书用户单聊发送 PDF 后，机器人能回复处理结果。
2. 发票代码和发票号码重复时不会重复入库。
3. Web 端可以查看、筛选、修正发票。
4. 可以选择抬头和目标金额，获得推荐发票组合。
5. 可以生成 A4 双拼 PDF 并下载。
6. 不同用户之间数据完全隔离。
7. 数据库使用 SQLite，无需额外安装数据库服务即可运行。
8. OCR 识别使用阿里云 API，识别失败时有降级处理。
